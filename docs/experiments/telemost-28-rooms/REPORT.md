# Повторная проверка Телемоста: 28 комнат и два IP

Длительный этап завершён: **28 комнат, 2.00 часа**. Контрольные HTTP-запросы: 6633/6720; передачи файлов: 1344/1344; ответы 429: 0. Строгий тест без ошибок — не прошёл.

Без одновременной передачи файла в той же комнате: 6045/6045 успешных проверок связи; при пересечении с передачей файла: 588/675. Эти счётчики относятся ко всему двухчасовому этапу.

Причина ограничения пока не установлена. Отсутствие 429 означает только, что предел не достигнут в выполненной конфигурации.

| two-ip-28-endurance | 28 / 28 | 120.0 | 6633/6720 | 1344/1344 | 0 | не прошёл |

Время выдержки не включает дополнительные финальные передачи файлов. «Не пройден» означает, что строгий критерий всех успешных проверок не выполнен; точные ошибки и длительность приведены в строке этапа и исходных измерениях.

За весь запуск зарегистрировано 12 сетевых ошибок API; максимальное время такого запроса — 20.001 с. Неудачных попыток SSH: 0, перезапусков обратного проброса: 0. Ошибка API без HTTP-ответа не считается ответом 429.

Один аккаунт и один набор из 28 комнат. Сначала все процессы работают на Mac с одним внешним IP. Затем десять серверных процессов перенесены на VPS, остальные 18 и все клиенты остаются на Mac. Второй этап выполнен в течение двух часов после готовности всех комнат. Смена IP также меняет машину и маршрут; это не полностью изолированный опыт над одним сетевым параметром.

Проверки связи идут каждые 30 секунд независимо от фоновых передач файлов. Каждые пять минут проверяются загрузка и отправка 1 МиБ для каждой комнаты, параллельно до восьми передач. Проверяется размер и SHA-256. Это периодическая нагрузка, а не непрерывное насыщение всех каналов. Номинальный опрос приёмной — 120 секунд после подключения; фактический интервал есть в summary.json.

Для передачи задан бюджет 60 секунд; внешняя обёртка завершает зависший процесс проверки через 75 секунд. Передачи дольше прежнего порога 30 секунд отдельно считаются медленными. Ошибки сохраняются и не заменяются удачными повторами. Единичный таймаут файла не прерывает всю выдержку; итог с любой ошибкой передачи не считается чистым. Три подряд неудачные проверки связи, повреждение данных, три ответа 429 и превышение ресурсных ограничений останавливают этап.

GET-запросы к API повторяются до трёх попыток при сетевом сбое или 502/503/504, через ту же очередь. Неоднозначно завершившийся POST не повторяется. Обработка 429 соблюдает Retry-After и общую задержку. Отменённые запросы покидают очередь; поздние ответы учитываются, повторная доставка отчёта не удваивает счётчики.

В локальной копии headless-client исправлена отмена HTTP/1.1: истёкший контекст закрывает сокет и исключает его из пула. Срок действует на запись, ожидание заголовков, чтение и закрытие тела. До исправления отдельный API-запрос завис на 225 секунд; регрессионный тест воспроизвёл отсутствие отмены на всех четырёх этапах. После исправления тесты с проверкой гонок проходят, обычное повторное использование соединения сохраняется. Для POST отключён также неявный повтор внутри Chrome-транспорта.

Команды SSH используют общий транспорт, ограниченные повторные попытки и отдельный приватный журнал ошибок. Обратный проброс работает отдельным процессом без мультиплексирования и контролируется независимо. Повтор запуска на VPS сверяется с уже работающим процессом. Завершение восстанавливает исходный прототип, включая его временный сервис, и проверяет передачу данных.

Границы: один конкретный аккаунт, две сети, без мобильных белых списков. Отсутствие 429 не устанавливает квоту сервиса и не доказывает, учитывает ли Яндекс аккаунт или IP. Число созданных ссылок не равно числу работающих туннелей; готовность проверяется передачей данных.

Управляющие скрипты параметризованы для отдельного стенда; адреса, ключи, сессии, ссылки на комнаты, сырые логи и восстановление конкретного частного прототипа исключены.
